# Languages and the French pack

Kohevo ships in **English** and **French**. English is the source language; every string the code renders has a
French entry, and CI keeps it that way.

## Where the strings live

| Scope | Files | Loaded |
|---|---|---|
| Core (admin, portal, errors, landing) | `lang/en.php`, `lang/fr.php` | always |
| Booking | `plugins/booking/lang/{en,fr}.php` | when the plugin is active |
| Forms (incl. the public form's JS messages) | `plugins/forms/lang/{en,fr}.php` | when active |
| Membership | `plugins/membership/lang/{en,fr}.php` | when active |
| Stripe Payment, Coaching, Backups, MCP Gateway, Media Library | `plugins/<slug>/lang/fr.php` | when active (English is the inline fallback) |

Each file returns a flat `key => text` array. In code, text is always `__('key', 'English fallback')` —
the fallback keeps the UI readable if a key is ever missing.

**Load order** (later wins), see `src/Services/I18n/I18n.php`:

1. core `lang/<locale>.php` (falls back to `en.php`)
2. plugin packs registered through the `i18n_lang_paths` filter
3. per-tenant overrides in the `lang_overrides` table (edited in the admin with **Multilang Translate**)

## Turning French on

French becomes *selectable* once the language registry offers it — the **Multilang Translate** plugin (or, on an
install without it, Membership) adds `fr` through the `i18n_supported_languages` filter. Then:

1. *Admin → Settings → General → Default language* → **Français**. This sets the `default_language` setting.
2. Visitors can switch with the language switcher (Multilang Translate) or `?lang=fr`, which is remembered in
   their session.

> Both `default_language` and the language registry live in the **database**, so a fresh install has to repeat
> step 1; shipping the files alone does not switch a site to French.

Date formatting follows the locale: `date_format_default` is `F j, Y` in English and `j F Y` (day first) in French.

## Adding or changing text

1. Use `__('area_short_key', 'English text')` in the code (never concatenate translated fragments — use
   `sprintf()` placeholders: `__('greeting', 'Hello %s,')`).
2. Add the key to the area's `en.php` **and** `fr.php`.
3. Run the check:

   ```bash
   php scripts/check-i18n.php
   ```

   It fails if a key used in code has no French entry, or if an `en.php` key is missing from its `fr.php`.
   CI runs it on every push and pull request.

Adding another language (say `de`): create `lang/de.php` and each plugin's `lang/de.php`, register the language
in Multilang Translate, then extend `scripts/check-i18n.php` to require it.

## Known gaps

The check covers strings that go through `__()`. These are **intentionally or knowingly** still English:

- Admin-only JavaScript (media picker, Multilang Translate admin screens).
- The MCP Gateway's machine-facing tool text, backup job logs, and internal exception messages.
- Seed copy for the built-in form templates, and the coaching summary note.
- The installer's `.env` write-failure message.

Public-facing pages, emails, validation messages, the customer portal and the main admin screens are translated.
